# 长文档多期拆分方法论

> 本文档在 SKILL.md 主流程外，仅在**预估时长超过 20 分钟（>8 个知识段落）**时需要阅读。
> 触发条件、时长估算口径见 SKILL.md 第四步"时长估算规则"。

拆分目标：每期 ≤ 20 分钟（6-8 个知识段落），在知识的"天然断点"处切割，期与期之间用钩子衔接。

---

## 拆分原则

1. **按知识依赖拆分**：在依赖关系的"天然断点"处分割
   - 前置概念讲完 → 一期结束
   - 新的大主题开始 → 新一期开始
   - 例：信号模型 → 一期；检测算法 → 二期；性能评估 → 三期

2. **按难度层级拆分**：
   - 基础概念（1-2 期）→ 进阶方法（1-2 期）→ 应用与展望（1 期）

3. **避免在以下位置切割**：
   - 一个公式的讲解中间
   - 一个类比还没讲完的地方
   - 提问者的追问还没被回答的地方

---

## 每期结构设计

```
第 N 期（共 M 期）：副标题

开场：
  - 首期：正常开场，介绍总主题 + 本期聚焦
  - 非首期：回顾上期要点（1-2 句）+ 本期预告

主体：5-6 个知识段落（20 分钟内）

结尾：
  - 非末期：总结本期 + 悬念钩子引出下期
  - 末期：总结本期 + 全系列回顾
```

---

## 期与期之间的衔接钩子

**结尾钩子**（非末期结尾必须有）：
- 提问者设悬念："不过我有个疑问，噪声环境下这些方法还管用吗？"
- 讲解者预告："这个问题很好，下一期我们就会看到，答案其实出乎意料..."
- 或用总结 + 反转："总结一下今天讲的都是理想情况。但现实中...嗯，事情没那么简单。"

**开场回顾**（非首期开头必须有）：
- 提问者回顾："上期我们聊了信号模型的基础，知道了回波长什么样。但光知道信号长什么样还不够，还得能从噪声里把它捞出来。"
- 讲解者衔接："没错，今天就来解决这个核心问题——检测。"

> 钩子的作用：让听众即使单独听某一期也能接上上文，同时制造"想听下一期"的牵引。不要用"下期再见"这种空洞寒暄代替钩子。

## 多期生成流程

```
源文档分析完成
      │
      ▼
  ① 生成分集大纲（00_总览与分集规划.md）
      │  包含：每期标题、覆盖的知识点、时长预估、切分依据
      ▼
  ② 向用户展示分集方案，等待确认
      │  用户可调整：合并/拆分某期、调整顺序
      ▼
  ③ 逐期生成脚本（每期独立文件）
      │  每期生成后都展示给用户审阅
      ▼
  ④ 逐期生成音频（或批量）
```

---

## 分集大纲模板

```markdown
# 播客分集规划

> 源文档：XXX.md（共 N 行）
> 总预估时长：约 X 分钟
> 分为 M 期，每期 ≤ 20 分钟

## EP01：基础概念（约 18 分钟）
- 覆盖章节：第 1-3 章
- 核心知识点：A、B、C
- 切分依据：基础概念独立完整，为后续打基础

## EP02：核心算法（约 20 分钟）
- 覆盖章节：第 4-6 章
- 核心知识点：D、E、F
- 切分依据：算法讲解需要前置知识 A/B/C，天然承接 EP01
- 开场回顾：回顾 EP01 的 A 概念

## EP03：实验与总结（约 15 分钟）
- 覆盖章节：第 7-8 章
- 核心知识点：G、H
- 切分依据：实验验证需要理解算法，放在最后
- 开场回顾：回顾 EP02 的核心算法
```
