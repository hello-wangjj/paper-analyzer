# 公式处理指南

## 公式优先级分级

### A级公式（必须看懂）
- 核心目标函数
- 核心模块定义
- 关键更新规则
- 关键理论结论

### B级公式（建议理解）
- 目标函数展开
- 中间等价变形
- 局部模块细节

### C级公式（知道用途即可）
- 标准推导步骤
- 与主结论关系较弱的辅助公式
- 附录中不直接支撑核心主张的证明细节

主报告中至少对 **3-8 个关键公式** 做深入解释，优先覆盖 A 级公式。

## 就地插入原则

公式解释应像图片插入一样，分发到最适合的上下文位置。严禁单独设置"公式理解卡集中区"。

插入位置：
- 与任务定义直接相关的公式 → `1.2 问题设定`
- 与建模目标、变量定义相关的公式 → `2.2 问题形式化与建模选择`
- 与核心模块、损失函数、更新规则相关的公式 → `2.3 核心推导与算法构造`
- 与理论边界、假设相关的公式 → `2.4 理论结论的适用范围`
- 与实验指标、消融机制直接相关的公式 → `3.x` 相关位置

## 三层翻译

每个关键公式至少包含：

1. **一句话直译**：这条公式本质上在做什么
2. **技术拆解**：每一项、每个符号分别表示什么
3. **工程映射**：它在代码/训练流程/推理流程里对应什么

## 就地公式解释模板

每个关键公式在所在上下文附近，尽量补充：
- 公式编号
- 这条公式在这里负责什么
- 符号说明
- 自然语言翻译
- 分项拆解
- 训练/推理中的作用
- 代码中的典型对应
- 若删去该项会怎样
- 是否依赖强假设

## Toy Example

对最关键的 1-3 个公式，若可行，提供一个极简数值例子，放在公式首次被重点解释的位置附近。

## Markdown 数学公式格式

### 强制格式
- 行内公式：`$...$`
- 跨行公式：独立的 `$$ ... $$`

### 禁止写法
- 用反引号包裹数学内容（变量、行内公式、公式块）
- 把公式写成普通文本
- 在公式块中使用 `\tag{}`
- 在 display 公式中裸写以 `+`、`-`、`*` 开头的行（会被 Markdown 渲染器当成列表）

### 反引号边界
- "公式解释、符号说明、toy example、理论推导、指标定义"区域 → 数学对象写成 `$...$`
- "代码映射、工程实现、命令示例"区域 → 真代码保留反引号
- 同一行同时出现数学和代码时：数学用 `$...$`，代码用反引号

### 多行公式
能单行就单行；不能单行才用 `aligned`：

```markdown
$$
\begin{aligned}
\mathcal{L} ={}& \lambda_1 \mathcal{L}_1 \\
&+ \lambda_2 \mathcal{L}_2
\end{aligned}
$$
```

不要把公式拆成没有环境保护的多行裸写。

### 降级策略
如果目标环境不支持数学渲染：
1. 保留原始 LaTeX 公式
2. 紧跟一段自然语言解释
3. 再补一行纯文本伪公式

## 公式编号

公式编号写在正文中（如"式 (3) 定义了损失函数"），不要在公式块内使用 `\tag{}`。
