# Reviewer Rubric

## 核心审稿目标

围绕"论文主张是否被原文和实验真正支撑"组织整篇分析，而不是围绕"这篇论文大概讲了什么"写摘要。

## 主张分类

始终把结论拆成三层：

1. **作者显式主张**
   - 原文明确宣称的贡献、结论、优势、限制
   - 需要绑定章节、表格、公式或实验位置

2. **隐含但有原文支持的主张**
   - 原文没有一句话直接说出，但可以由可见证据稳妥推出
   - 必须同时写明支持证据与外推边界

3. **你自己的推断**
   - 只能放在"质疑 / 可能解释 / 边界讨论"里
   - 不得写进正式贡献表述或结论表

## 证据链要求

每个重要判断都尽量补全证据链：

- 论文原文位置
- 相关公式 / 图表 / 实验
- 该证据支撑的是哪条主张
- 证据能支撑到什么强度
- 还缺哪些环节

如果实验不能直接闭环某条主张，明确写"证据链未闭环"。

## 主张表格式

| 主张 ID | 主张内容 | 显式或隐含 | 原文位置 | 证据类型 | 结论强度 |
|---|---|---|---|---|---|

- **证据类型**：理论分析 / 方法设计 / 主实验 / 消融实验 / 失败案例 / 外部文献对照
- **结论强度**：强支撑 / 部分支撑 / 间接支撑 / 证据不足

## 实验-主张对应矩阵格式

| 实验组 | 对应主张 | 是否充分验证 | 缺失项 |
|---|---|---|---|

优先回答：
- 这组实验到底想验证什么
- 是否有更直接的对照组
- 是否缺统计显著性、多 seed、失败案例或关键消融

## 表格审稿要求

### 主结果表
- 必须转录论文中最关键的主结果表原始数值
- 不允许只写"优于 baseline"这种段落式总结
- 每张表后追加审稿人提示：支撑哪条主张 / 直接还是间接证据 / 是否存在实验-结论错配

### 关键消融表
- 必须优先转录与核心机制直接相关的消融表
- 不能只用口头描述替代表格
- 每张表后追加审稿人提示：是否真的隔离了机制差异 / 是否有更简单的替代解释 / 缺了什么对照

## 写作时持续追问

- 问题设定是否真的存在，还是对旧问题的重新包装
- 创新是机制改变，还是已有方法的重组 / 参数化 / 工程增强
- 推导是否强依赖 i.i.d.、线性化、无限样本等强假设
- 实验指标是否真能映射到论文宣称的优势
- 工程现实是否会破坏理论优势
- 是否存在更简单、同样能解释结果的替代机制

## 图片与表格插入规则

图片和表格必须"图随论证走"，严禁集中堆放：

- 任务设定图 / 总体结构图 → `1.2 问题设定`
- 方法总览图 / 模块图 → `2.3 核心推导与算法构造`
- 主结果可视化 → `3.3 实验结果的解释力度`
- 失败案例图 → `3.4 潜在未讨论因素`
- 消融相关图 → `3.3` 或 `3.4`

表格同理：
- 主 benchmark 表 → `3.3` 正文 + 附录 A
- 消融实验表 → `3.4` 正文 + 附录 A
- 附录不能替代正文中的对应表格
