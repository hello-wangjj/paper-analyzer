# Changelog

技能版本记录（倒序）。升级时同步 frontmatter `version` 与本文。

## v1.1.0 (2026-10-19)

- `check` 的 §3 从"工作区存在"升级为"sha:path 在 Git 对象中存在"，并校验行号不越界；未提交的产物不再能用路径蒙混过关，必须内联或先提交。
- `[x]` 的验证要求至少两个非标点字符，空验证与单破折号不再通过。
- 新增 front matter 一致性校验：`task` 必须等于文件名，`head` 必须存在于仓库，`project_root` 必须是绝对路径（拒绝 MSYS `/c/...`）。
- 新增九节序号校验与 §9 交接链格式校验；未闭合围栏会报出真因，而不是只报"缺节"。
- 移除 `new --force`：重复交接改为直接编辑现有文件，避免一键清空 §9 历史。
- `new` 拒绝空值、多行标题与不存在的 `--root`；模板变量改为单次替换，标题里的 `{{...}}` 不再被二次展开。
- 修正两处误报：`dt < 阈值 > 0` 不再被判为未替换占位符；`[x]` 下缩进的 `- 验证：...` 不再被判缺验证。
- 文档同步：明确校验器只保证本机仓库内的可机械判定项，跨机器可达性仍由 §1/§7 负责。

## v1.0.0 (2026-10-17)

- 首个版本：跨工程 / 项目 / agent / 工具 / session 的单文件交接契约
- 记录位置定为 `<工作根>/.handoff/<task>.md`，随仓库走、覆盖写、§9 追加交接链
- 九节契约：目标与验收、当前状态、在途产物、锁定决策、已否决路径、环境与重建、授权与风险、下一步、交接链
- 四条硬规则：零虚构、verbatim 优先（路径 + sha + 行号，磁盘上没有的整段粘贴）、已完成必须带验证、凭据只写位置
- 四种边界：context-exhaustion / tool-switch / agent-handoff / migration，各自的额外要求与检查清单
- `scripts/handoff.py`：`new` 脚手架（自动取 branch / head）、`check` 校验（结构、占位符、路径可达性、`[x]` 证据）、`list` 检索
