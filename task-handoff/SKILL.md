# 任务交接（task-handoff）

交接不是"告诉对方发生了什么"，而是**让对方不必问你就能继续做，并且能验证你说的话**。一份合格的交接记录，接手方读完能直接动手，且知道什么不能动、什么已被否决、怎么算做完。

## 何时用 / 何时不用

| 场景 | 用不用 |
|---|---|
| 上下文将满，换 session 续接 | 用 |
| 换客户端或模型（Claude Code / Codex / WorkBuddy / ZCode / kilo / opencode） | 用 |
| 把任务交给同事、另一个 agent 或专家角色 | 用 |
| 任务从一个仓库迁到另一个仓库 | 用 |
| 同一 session 内拆解步骤 | 不用，用任务列表 |
| 转发一个问题给专家 | 不用，直接说 |
| 需要长期任务板、状态流转、多角色认领 | 不用，本技能只保交接点，不做状态机 |

## 交接单元：一个任务一个文件

```
<工作根>/.handoff/<task-slug>.md
```

- **工作根** = 任务所在 git 仓库根；无仓库时 = 当前工作目录。不设全局目录，不设 v2/v3 副本。
- 理由：记录必须和代码**同源、同 sha、同一次 commit** 到达接手方。放在全局目录或聊天里，换机器就断。
- 重复交接：**覆盖同一个文件**，历次交接一行一条追加到 §9，历史不另存。
- 记录默认入仓（可提交）。如果任务内容不宜公开，由你自行决定不入仓；本技能不提供第二套路径。

## 三个动作

1. **建**：`python scripts/handoff.py new --root . --task <slug> --title "<标题>" --boundary <类型> --to "<接手方>"`
2. **写**：按 §1–§9 填满，遵守下面四条硬规则。删除模板里所有以 `>` 开头的说明行。
3. **校验**：`python scripts/handoff.py check`，错误清零再交付。接手方用 `list` 找记录。

## 契约九节

| 节 | 必须回答 | 缺失后果 |
|---|---|---|
| 1 目标与验收 | 一句话目标；可执行或可观测的完成判据；明确不做什么 | 接手方做出"更好"但不对的东西 |
| 2 当前状态 | 已完成（每条带验证）、在途、未动 | 重复劳动，或把半成品当成品 |
| 3 在途产物 | 每个产物的可达位置 + sha/行号；磁盘上没有的整段粘贴 | 接手方重新生成而不是续写，结果必然不同 |
| 4 锁定决策 | 已定结论 + 理由 + 影响 | 重新争论，来回改 |
| 5 否决路径 | 试过什么、失败现象是什么 | 再踩一遍同样的坑 |
| 6 环境与重建 | 运行时/版本/依赖/变量名/凭据位置/构建测试命令/已知坑 | 环境起不来，误判为代码坏了 |
| 7 授权与风险 | 谁拍板、可改范围、禁区、未决问题、阻塞 | 越权改动；卡住了不说 |
| 8 下一步 | 唯一的第一个动作 + 之后三步 | 从错的入口开始 |
| 9 交接链 | 每次交接一行：时间、从→到、边界类型、摘要 | 丢失历史，无法追溯 |

字段级定义与判定规则见 [references/contract.md](references/contract.md)。

## 四条硬规则

1. **零虚构**。只写本次实际发生的事。不确定就写 `unclear` 并指定由谁确认，不要补全、不要润色成结论。
2. **verbatim 优先**。磁盘上存在的产物给 `路径 @ sha : 起-止行`，且路径必须**从接手方可达**；磁盘上不存在的（聊天里的草稿、口头定的方案）必须整段粘贴进围栏代码块。禁止"见上文""同上""如前所述"。
3. **已完成必须有证据**。§2 里每一项 `[x]` 后面必须跟 `验证：<命令或观测>`。没跑过就不许打勾；"应该能编译"不算验证。
4. **凭据只写位置**。写环境变量名、密码库条目、由谁提供。任何密钥、token、口令、内网地址的值都不进记录。

## 四种边界，各自额外盯住什么

| boundary | 额外要求 |
|---|---|
| `context-exhaustion` | 时间紧，先保 §3 和 §8。宁可少写分析，不可少交产物。 |
| `tool-switch` | §6 必须能从零重建；全文禁止引用任何客户端私有状态（会话 id、"上文"、应用内临时目录、只有某工具能读的引用）。 |
| `agent-handoff` | §7 必须写清决策权与验收人；§1 的判据要能被第三方独立判定，不能依赖你的主观判断。 |
| `migration` | §6 必须给路径映射表（源→目标）+ 依赖与外部契约是否随迁；§3 的引用要指向目标仓可访问的位置。 |

逐类检查清单见 [references/boundaries.md](references/boundaries.md)。

## 接手方协议

读序：§1 → §2 → §3 → §4 → §5 → §8，动手前读 §6。

三条禁止：不重开 §4 已锁定的决策；不重试 §5 已否决的路径；不改写记录里的历史（只追加 §9 并更新 front matter）。

发现记录与代码不一致，**以代码为准**，把差异写进 §7，不要默默修正，也不要按记录去改代码。

接手后：`status` 改为 `active`，`to` 改成本次执行者，§9 追加一行。

## 命令

```bash
python scripts/handoff.py new --root . --task kf-tuning --title "KF 参数整定" \
    --boundary tool-switch --to "Codex/gpt-5"
python scripts/handoff.py check .handoff      # 也可传单个 .md
python scripts/handoff.py list               # 不给参数时向上找 .handoff
```

退出码：`0` 无错误（可能有 WARN）、`1` 有 ERROR、`2` 用法或 IO 错误。WARN 不影响退出码。

## 常见失败模式

| 失败 | 表现 | 修法 |
|---|---|---|
| 摘要代替产物 | "完成了 KF 调参，详见代码" | §3 给路径+sha+行号，或整段粘贴 |
| 路径不可达 | 用了本地绝对路径、临时目录、未提交文件 | 换成仓库相对路径 + sha；跨仓给绝对路径并确认对方可读 |
| 计划写成已完成 | 打了 `[x]` 但没有验证命令 | 降回 `[ ]`，或补命令与结果 |
| 只交接结论不交接判据 | "你看下合不合适" | §1 写成可判定的判据，§7 指定验收人 |
| 写完不校验 | 段落空着、占位符没替换 | 交付前跑 `check`，ERROR 清零 |
