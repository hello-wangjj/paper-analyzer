# 交接契约：字段定义与判定规则

本文是 `SKILL.md` 与 `scripts/handoff.py` 的共同依据。改契约时三处同改：本文、`assets/template.md`、脚本里的 `SECTIONS` / 枚举 / 校验规则。

## 1. 物理约定

| 项 | 规则 |
|---|---|
| 位置 | `<工作根>/.handoff/<task>.md` |
| 工作根 | 任务所在 git 仓库根；无仓库时当前工作目录 |
| 文件名 | `task` 字段 + `.md`，两者必须一致 |
| 粒度 | 一个任务一个文件，覆盖写；不建 v2、不建日期副本 |
| 编码 | UTF-8（无 BOM 亦可），建议 LF |
| 入仓 | 默认提交。涉密任务由作者决定不入仓，本技能不设第二套路径 |
| 发现 | 接手方从 cwd 向上找 `.handoff/`；找不到就问，不要猜 |

**为什么不用全局目录**：记录的价值在于和代码同 sha、同一次 commit 到达接手方。放进 `~/.handoff` 后，换机器、别人 clone、回滚分支都会让记录与代码脱钩，而脱钩的交接记录比没有更危险。

## 2. front matter

扁平 `key: value`，不嵌套、不用列表。脚本只解析这一种形式。

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `handoff` | 是 | `1` | 契约版本。结构不兼容变更时递增 |
| `task` | 是 | ASCII slug | 跨多次交接保持不变，等于文件名 |
| `title` | 是 | 自由文本 | 人读标题 |
| `status` | 是 | `waiting` / `active` / `blocked` / `done` / `abandoned` | `waiting` = 已写好待人接手；`active` = 有人在推进 |
| `boundary` | 是 | `context-exhaustion` / `tool-switch` / `agent-handoff` / `migration` | 决定 §6、§7 的额外要求 |
| `from` | 是 | `<工具>/<模型>` 或人名 | 交接方 |
| `to` | 是 | 同上；未指定写 `unassigned` | 接手方 |
| `updated` | 是 | `YYYY-MM-DDTHH:MM+08:00` | 最后一次写记录的时间，不是任务开始时间 |
| `project_root` | 否 | 绝对路径（正斜杠） | §3 路径解析基准；缺省为 `.handoff` 的上级 |
| `branch` | 否 | 分支名；非 git 写 `-` | 接手方据此判断是否要切分支 |
| `head` | 否 | 短 sha；非 git 写 `-` | 记录对应的代码版本。与当前 HEAD 不一致时，接手方应先看差异 |

`status` 的流转：`waiting` →（接手）→ `active` →（交接或完成）→ `waiting` / `done` / `blocked` / `abandoned`。谁写记录谁负责把 `status` 写对；不要留 `active` 而人已离开。

## 3. 正文九节

标题必须是 `## <序号>. <标题>`，顺序不可换，标题文字不可改（括号补充允许，如"在途产物（verbatim）"）。脚本按标题文字匹配，按序号判断顺序。

### §1 目标与验收

- **目标**：一句话，动宾结构。"优化 KF"不合格；"把 KF 的位置 RMSE 在 nuScenes mini 上从 0.42 降到 0.30 以下"合格。
- **完成判据**：`- [ ]` 列表，每条要么是可执行命令，要么是可直接观察到的结果。判据要能被第三方独立判定。
- **不在范围内**：显式排除。这一栏防止接手方"顺手"扩大改动面。

### §2 当前状态

- 三态：`[x]` 已完成、`[ ]` 在途（写进度与卡点）、`[ ]` 未开始。
- 每个 `[x]` 同行（或紧邻续行）必须有 `验证：<命令或观测>`。观测型也可，但必须写清"谁、在什么环境、看到什么"。
- 禁止把"计划做"写成"已做"。判断标准：现在能否复现这个结果。

### §3 在途产物（verbatim）

这是整份记录里最贵的一节，也是最容易写坏的一节。

| 产物位置 | 写法 | 判定 |
|---|---|---|
| 仓库内文件 | `- 文件：\`src/kf.py\` @ \`9f3c2ab\` : \`120-186\` — 说明` | 路径以 `project_root` 为基准必须存在 |
| 仓库外文件 | 同上，路径写绝对路径 | 必须存在；临时目录会告警 |
| 磁盘上不存在 | `- 内联：` + 围栏代码块整段粘贴 | 必须出现围栏；正文不得改写、不得摘要 |
| 目录产物 | 路径指向目录 + 目录内清单 | 目录必须存在 |

规则来源：只给描述，接手方会**重新生成**，重新生成的东西永远和原来不一样。给路径 + sha + 行号，才是"同一个东西"。

sha 的选择：写产物最后一次有效修改所在的 commit。若产物尚未提交，写当前 `head` 并在 §7 注明"未提交"。

### §4 已锁定决策

格式：`- **决策** — 理由：…；影响：…`。

收录标准（任一即可）：选了两个都可行的方案之一；改了原始需求；判定某需求不可行；接手方日后会问"为什么当初这么做"。

写进这节等于**冻结**。接手方不得重开讨论，除非提供新证据并在 §9 记录。

### §5 已否决路径

格式：`- **方案** — 失败现象：…；结论：…`。

"失败现象"必须具体：报错文本、指标没动、崩溃位置。写"效果不好"等于没写，接手方会认为值得再试。

首次交接确实没有否决项时写 `- 无：首次交接，未尝试其他路径`。不要留空，空白无法区分"没有"和"忘了"。

### §6 环境与重建

表格五格：运行时、依赖、环境变量、构建、测试；加"已知环境坑"列表。

- **凭据**：只写变量名与获取位置（`HANDOFF_DB_URL`，值见密码库条目 `db/prod-ro`）。任何值都不写。
- **命令**：写可直接粘贴的完整命令，含工作目录假设。不要写"按常规方式构建"。
- **已知坑**：平台差异、路径分隔符、编码、代理、证书、必须的 shell。这一栏省一条，接手方多花半小时。
- **路径映射**（仅 `migration`）：源路径 → 目标路径两列表。语义变更（不只是路径变化）要单独注明。

### §7 授权与风险

四块：

- **决策权**：谁拍板；哪些范围内接手方可自决。
- **可修改范围 / 禁止触碰**：用目录或文件路径，不用"核心模块"这类模糊表述。
- **未决问题**：`- 问题 — 需要谁决定；当前按什么假设推进`。假设必须显式，否则接手方会把假设当结论。
- **风险与阻塞**：触发条件 + 影响面。

`unclear` 只允许出现在本节和 §1，且必须带"由谁确认"。

### §8 下一步

- **第一步**必须唯一、动词开头、可直接执行。"继续开发"不合格；"在 `src/kf.py:120` 把 Q 矩阵从常量改为按 dt 计算，然后跑 `pytest tests/test_kf.py -k rmse`"合格。
- **之后三步**给方向，不必给细节。超过三步说明还没想清楚，回 §1 重新拆。

### §9 交接链

每行格式：`- YYYY-MM-DD HH:MM · 从 → 到 · boundary · 一句话`。

只追加，不改写。这一节是审计轨迹：谁在什么时候把什么交给了谁。任务结项后仍保留。

## 4. 校验器判定表

| 级别 | 触发条件 | 退出码 |
|---|---|---|
| ERROR | 缺 front matter / 缺必填字段 / 枚举非法 / 时间格式错 / 缺节 / 节重复 / 节顺序错 / 某节为空 / 含省略式引用或占位符 / §2 的 `[x]` 无验证 / §3 路径不可达或引用临时目录 / §9 无条目 | 1 |
| WARN | task 非 slug / head 非 sha / project_root 不存在 / 某节内容过短 / §3 条目未按约定前缀 | 0 |
| OK | 以上均无 | 0 |

校验器**不判断内容质量**。它只保证：结构完整、没有静默省略、引用的东西真的存在、打勾的项有证据。质量由 §1 的判据和 §7 的验收人负责。

## 5. 反模式

| 反模式 | 为什么错 |
|---|---|
| 用 `>` 引用块写正文 | 校验器把说明块排除在内容之外，正文会判为空 |
| 在 §3 粘贴代码又同时给路径 | 双份内容必然漂移，只能留一份 |
| 把整份聊天记录贴进来 | 噪声淹没结论，接手方仍要自己判断 |
| `status: done` 但 §8 还有下一步 | 状态与内容矛盾，接手方不知道是否该动手 |
| 交接给"更强的模型"所以写得简略 | 能力不替代上下文，缺的字段照样缺 |
