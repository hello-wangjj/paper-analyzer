# 公式处理指南

## 公式选择：四条判据

公式数量由论文决定，不设配额。仅当满足以下至少一条时才在正文深入解释：

- 它定义论文核心机制；
- 它是训练目标中真正有新意的部分；
- 它决定理论结论的成立条件；
- 它直接解释关键实验或消融。

标准指标、坐标变换、常规 softmax、普通交叉熵和附录统计公式，除非改变结论，否则移入附录 B。移入不是删除：凡是支撑核心 Claim、复现或审计所必需的公式，都要在附录 B 保留定位和作用说明。

不输出"A 级公式 / B 级公式 / 公式理解卡"等内部工作标签；分级只是选择工具，按自然叙事写。

## 就地插入原则

公式解释像图片一样，分发到最适合的上下文位置，严禁单独设置"公式理解卡集中区"。

插入位置：

- 与任务定义直接相关的公式 → `1.1` / `2.1 研究对象、输入输出与关键前提`
- 与建模目标、变量定义相关的公式 → `2.1` 或 `2.2 核心机制`
- 与核心模块、损失函数、更新规则相关的公式 → `2.2 核心机制、协议或论证链`
- 与理论边界、假设相关的公式 → `2.4 假设、训练推理与实现边界`
- 与实验指标、消融机制直接相关的公式 → `3.2` / `3.3` 相关位置

## 解释顺序与三层翻译

每个正文关键公式按以下顺序解释：

1. **为什么需要它**：用 1-2 句说明它填补哪一步；
2. **先看一个例子**：给最小数值或场景例子，让读者先预测结果方向；
3. **原公式**（式 (n)）；
4. **关键符号**：只解释决定行为的关键符号（技术拆解）；
5. **训练/推理/证明中的作用**：它在机制里对应哪个步骤，删掉或改变关键项会怎样（工程映射：对应代码/训练流程/推理流程里的什么）；
6. **证据与假设边界**：它依赖什么强假设，实验支持到什么程度。

如果 toy example 比公式本身更复杂，省略 toy example，改用定性例子。

## 就地公式解释模板

```markdown
**为什么需要这条式子。** 用 1–2 句说明它填补哪一步。

**先看一个例子。** 给最小数值或场景例子，让读者先预测结果方向。

式 (n)：

$$ ... $$

- 只解释决定行为的关键符号；
- 说明它在机制、训练/推理、证明或分析中对应哪个步骤；
- 说明删掉或改变关键项会怎样；
- 说明证据和假设边界。
```

## Markdown 数学公式格式

### 强制格式

- 行内公式：`$...$`
- 跨行公式：独立的 `$$ ... $$`
- 公式编号写在正文中（如"式 (3) 定义了损失函数"），不在公式块内使用 `\tag{}`

### 禁止写法

- 用反引号包裹数学内容（变量、行内公式、公式块）
- 把公式写成普通文本
- 在公式块中使用 `\tag{}`
- 在 display 公式中裸写以 `+`、`-`、`*` 开头的行（会被 Markdown 渲染器当成列表）
- `\mathbbm` 等依赖额外宏包的命令；指示函数可写为 `\mathbf{1}_{\{\cdot\}}`

### 反引号边界

- "公式解释、符号说明、toy example、理论推导、指标定义"区域 → 数学对象写成 `$...$`
- "代码映射、工程实现、命令示例"区域 → 真代码保留反引号
- 同一行同时出现数学和代码时：数学用 `$...$`，代码用反引号

### 多行公式

能单行就单行；不能单行才用 `aligned`：

```markdown
$$
\begin{aligned}
\mathcal{L} ={}& \lambda_1 \mathcal{L}_1 \\
&+ \lambda_2 \mathcal{L}_2
\end{aligned}
$$
```

不要把公式拆成没有环境保护的多行裸写。

### 降级策略

如果目标环境不支持数学渲染：

1. 保留原始 LaTeX 公式
2. 紧跟一段自然语言解释
3. 再补一行纯文本伪公式

不要默认重复两种表达。
