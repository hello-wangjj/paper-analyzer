# Claim—Evidence—Verdict 审稿口径

## 核心审稿目标

围绕"论文主张是否被原文和类型匹配的证据真正支撑"组织整篇分析，而不是围绕"这篇论文大概讲了什么"写摘要。评价标准是"作者提出的 Claim 是否由适合该 Claim 的证据支持"，不是"报告是否凑齐图片、公式、表格或实验"。

## Claim 分类

始终把结论拆成三层：

1. **作者显式主张**：摘要、引言、贡献或结论中明确宣称；需要绑定章节、表格、公式或实验位置。
2. **有原文支持的隐含结论**：原文没有一句话直接说出，但可以由可见证据稳妥推出；必须同时写明支持证据与外推边界。
3. **报告推断**：只能放在"质疑 / 替代解释 / 边界讨论"（第 5 章）里，并标明推断依据。

不要把隐含结论或报告推断改写成作者贡献。

## Claim—Evidence—Verdict 总表格式

| Claim | 原文位置 | 作者证据 | 支撑强度 | 最大缺口 | 本报告结论 |
|---|---|---|---|---|---|

- **原文位置**：section / table / figure / equation / theorem / appendix，或代码路径。
- **作者证据**：注明实际类型——理论分析 / 方法设计 / 主实验 / 消融实验 / 反例 / 失败案例 / 协议 / 系统测试 / 外部文献对照。
- **支撑强度**：见下节五级。
- **最大缺口**：还缺什么关键对照、统计或证明步骤。
- **本报告结论**：该 Claim 被支持到什么范围，不能外推到哪里。

实验类论文的每组实验必须能在表中查到对应 Claim（即实验-主张对应关系）；若某组实验不对应任何核心 Claim，本身就是审稿发现。

## 证据强度（五级）

- **强支撑**：有直接、受控、充分规模的理论或实验闭环。
- **部分支撑**：方向一致，但缺少关键对照、统计或覆盖范围。
- **间接支撑**：证据与 Claim 相关，但存在替代解释。
- **证据不足**：证明、实验、协议或实现没有直接支持 Claim，或其语义与 Claim 不一致。
- **被反证**：论文自身结果或代码直接与 Claim 冲突。

每个等级都写明"什么证据会改变这个判断"。如果实验不能直接闭环某条主张，明确写"证据链未闭环"。

## 经验、数据与系统证据审查

优先检查：

1. 实验是否直接对应 Claim；
2. 最强且公平的 baseline 是否存在；
3. 一次实验是否同时改变多个变量；
4. 是否报告方差、置信区间、多 seed 或配对检验；
5. 相对提升是否掩盖低绝对水平；
6. 训练数据、测试数据或特权信息是否泄漏；
7. 失败案例是否覆盖结构性边界；
8. benchmark 指标是否真的映射到作者的现实叙述（如 MOTA 提升是否等价于车载场景跟踪更可靠）。

不要把"没有报告所有可能实验"当作局限。只保留会改变核心 Claim 的缺口。

按论文类型补充对应检查：方法论文看机制对照与消融；实证论文看效应量与统计不确定性；系统论文看接口语义与系统测试（吞吐/延迟/成本）；数据集 / benchmark 看数据覆盖、划分、泄漏和评测协议；综述 / meta-analysis 看检索、纳入、质量评估和异质性；观点论文看论证前提、反方观点和反例。不存在实验的论文不套用实验配额。

## 理论与公式边界

区分：定义 / 目标函数 / 启发式变换 / 定理 / 证明 / 经验现象。公式存在不等于理论保证；检查结论是否从局部等式、代理目标或强假设过度外推。

理论论文进一步检查：

- 定义域和量词是否与定理陈述一致；
- 假设是否被结论或应用叙述弱化、隐藏；
- 引理是否完整覆盖中心定理所需步骤；
- 证明是否存在循环依赖、边界遗漏或未经证明的关键跳步；
- 反例、极端情形和复杂度是否限制外推。

## 复现、验证与工程边界

若有公开代码，核对：

- 输入与论文任务定义是否一致；
- 训练和推理时可见信息；
- 损失、停止条件和指标实现；
- 默认超参数与正文/附录；
- fallback、缓存和后处理；
- 实车/实机部署是否依赖论文未强调的传感器或控制器。

静态代码核查不能写成"已经复现"。没有实际运行就明确说明。

理论论文把"复现"解释为验证：核对定理前提与证明依赖，尝试最小反例，必要时做符号/数值检查；未经机械核验不得写成"证明已验证"。数据论文核对数据许可、划分、预处理与评测脚本的一致性。

## 最终判断

最终判断（第 7 章）必须可行动，至少回答：

- 真正的新意是什么；
- 最强证据是什么；
- 最大未闭环问题是什么；
- 值得精读、浏览还是暂不投入；
- 若要复现或验证，最小判别路径是什么。

除非用户要求，不给无锚点的小数分数；用户要求打分时，先写明评分标准。

## 表格审稿要求

### 主结果表（实验类论文）

- 必须转录论文中最关键的主结果表原始数值（绝对值 + 最强基线差值）
- 不允许只写"优于 baseline"这种段落式总结
- 每张表后追加审稿人提示：支撑哪条主张 / 直接还是间接证据 / 是否存在实验-结论错配

### 关键消融表（实验类论文）

- 必须优先转录与核心机制直接相关的消融表
- 不能只用口头描述替代表格
- 每张表后追加审稿人提示：是否真的隔离了机制差异 / 是否有更简单的替代解释 / 缺了什么对照

### 非实验类论文

理论论文用假设—引理—定理—证明依赖、反例或复杂度边界作为证据载体；数据集/benchmark 优先数据组成、划分、协议和泄漏审查。原文没有某类证据不是缺陷，写"原文未提供"及判断影响即可。

## 写作时持续追问

- 问题设定是否真的存在，还是对旧问题的重新包装
- 创新是机制改变，还是已有方法的重组 / 参数化 / 工程增强
- 推导是否强依赖 i.i.d.、线性化、高斯噪声、无限样本等强假设
- 实验指标是否真能映射到论文宣称的优势（及车载场景需求）
- 工程现实（实时性、算力、内存、传感器噪声）是否会破坏理论优势
- 是否存在更简单、同样能解释结果的替代机制

## 图片与表格插入规则

图片和表格必须"图随论证走"，严禁集中堆放：

- 任务设定图 / 总体结构图 → `1.2 核心结构或论证链` 或 `2.1 输入输出与关键前提`
- 方法总览图 / 模块图 → `2.2 核心机制、协议或论证链`
- 主结果可视化 / 定性对比图 → `3.2 主结果与决定性证据`
- 失败案例图 / 消融相关图 → `3.3 关键消融、证明与补充证据`

表格同理：主 benchmark 表 → `3.2` 正文 + 附录 A；消融实验表 → `3.3` 正文 + 附录 A；附录不能替代正文中的对应表格。
