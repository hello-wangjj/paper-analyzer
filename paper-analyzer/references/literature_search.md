# 外部文献检索规则

## 目标

外部检索只用于改变以下判断：

- 论文是否真的首创；
- 最接近的技术路线是什么；
- 是否存在直接竞争或反对证据；
- benchmark、方法或结论是否被后续工作修正；
- 复现所需的官方代码、项目页或评测协议。

按判断需要核对真正相关的工作，优先覆盖最近方法、竞争路线和会改变判断的替代解释。数量不是目标；短理论结果、新问题或缺乏直接前作时可以只有少量来源，但要明确记录检索范围和未找到的证据，不得用弱相关工作凑数。

## 检索工具

优先使用宿主环境的 WebSearch / WebFetch 工具；宿主未提供时，调用本机 **websearch MCP**：

- `search_papers(query, limit, sources)`：聚合 arXiv / OpenAlex / Crossref / OpenReview（配置 `S2_API_KEY` 后自动含 Semantic Scholar），返回统一结构并已跨源去重——直接用于核对标题、作者、年份、venue 与链接
- `search_web(query, max_results)`：通用 web 搜索，用于官方项目页、代码仓库与 benchmark 页面
- `fetch_url(url, max_length, start_index, raw, fallback)`：**打开具体页面**取回正文 markdown（导航、广告、页脚已去），用于下一步的核对；JSON / 纯文本 / XML 原样返回

`fetch_url` 的返回带 `length`、`truncated`、`next_start_index`：长文先取一段，
需要时用 `start_index=next_start_index` 续读，不要一次把整页读进来。`via` 为
`"jina"` 表示该页经 r.jina.ai 兜底取回（多为 JS 渲染页），内容按同一标准核对；
`note` 说明了兜底原因。`error` 里出现"internal address"是本机/内网地址被拒的
预期行为，不要绕道尝试。PDF 只报提示不解析，改引 `oa_pdf_url` 或离线阅读。

MCP 聚合结果不能替代打开原文：仍须按"核对与写入"的标准，只有用 `fetch_url`
（或宿主 WebFetch）打开并核对过的来源才能写入报告；MCP 不可用时回到宿主工具，
两者都不可用时明确记录检索边界。

## 来源优先级

学术结论只接受真实、可核验来源，优先级从高到低：

1. 会议官网 / 期刊页面
2. OpenReview
3. arXiv 版本页
4. 作者主页或项目主页
5. 官方代码仓库
6. 机构仓库或其他可核验镜像

不要把博客、随手笔记、营销稿、聚合站摘要、搜索结果片段当成正式学术证据。

## 查询策略

每次只围绕一个可证伪问题检索，不要把多个问题混在一条查询里：

- 论文标题或方法名 + `project` / `code` / `review`
- 核心机制 + 最接近任务
- 方法族名称 + `limitation` / `critique` / `failure mode`
- 关键假设 + `alternative` / `counterexample` / `challenge`
- 任务设定 + benchmark + `comparison` / `evaluation`
- 论文作者 + `response` / `discussion` / `revision`

优先从原论文 references 找最近工作，再补论文发表之后的直接相关工作。

## 对照要求

文献对照（第 4 章）至少覆盖两类：

1. **主流支持路径**：该论文延续了什么研究方向，哪些代表工作与其结论一致。
2. **竞争或反对路径**：是否已有工作质疑其假设，是否有方法用更简单的机制解释同类结果。

## 核对与写入

写入报告前必须打开来源并核对：

- 标题、作者、年份和发表状态；
- 该工作实际提出的技术；
- 它与目标论文的具体一致或分歧点。

明确写出论文名或作者名，只总结你确认过的结论。不要把"相关"自动写成"支持"，也不要把不同任务上的负结果写成直接反驳。若无法判断是"支持"还是"平行相关"，写成"相关但未形成直接支持证据"；若未检索到明确反对或支持证据，直接写"当前未检索到明确反对或支持证据"。

- 优先引用与论文问题设定直接相关的工作
- 不要用无关但热门的论文凑"相关工作"
- 若引用 preprint，标清其为 `arXiv / preprint`

## 引用规范

附录 C 只列正文实际引用并已打开核对的论文或官方页面，四列格式：

| 文献 | 直接链接 | 与本文的具体关系 | 在本报告中的用途 |
|---|---|---|---|

每条必须包含可点击的官方或 arXiv 直接链接，并说明它在报告中用于支持哪项比较、边界或替代解释。若报告未使用外部文献，明确说明原因，不能留空。

找不到直接证据时写：

> 当前未检索到对该具体机制的直接支持或反对证据；以下工作只构成竞争路线。
