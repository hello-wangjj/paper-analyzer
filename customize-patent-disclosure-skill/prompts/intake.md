# 边界与输入录入（Step 1）

## 用途

在开始专利挖掘与交底书撰写前，用**少量问题**收敛案件边界。信息不全时可跳过，由 Agent 后续推断并**注明假设**。

## 可选开场

```
为便于挖掘专利点与组织交底书，先确认几项边界；可跳过，将按已有材料推断。
```

## 问题序列

### Q1：技术主题或产品模块

```
请用一句话描述本方案所属技术主题或产品模块，例如「多模态检索排序」「工业质检缺陷分级」「车载毫米波雷达目标跟踪」。
```

### Q2：专利类型（发明 / 实用新型）

```
本案封面「申报类型」倾向哪一类？发明 / 实用新型 / 暂不确定
```

**默认规则（硬性）**：

- 用户**未显式**指定时，**统一默认 `发明`**，并在汇总中写明「专利类型：发明（默认）」，封面表「申报类型」随之填「发明」。
- 仅当用户明确说「实用新型」时才切换（所内模板不涉及外观设计）。
- 「暂不确定」或跳过 Q2 → 仍按**发明**推进；可在材料扫描或预览阶段用下方「反问」校正。

**与权利要求形态区分**：方法 / 系统 / 装置属于**权利要求书式倾向**（见 `disclosure_builder.md` §7.6 交互），**不是**本问的专利类型。若用户只答「方法/系统」，仍默认专利类型为发明。

**联动**：查新时把类型传给检索工具：`--type invention` 或 `--type utility_model`（见 `prior_art_search.md` §A.3）。

### Q3：文头联系人

```
交底书封面表的技术联系人是否需要占位？需要则提供姓名/电话/邮箱；不需要则全部写「[待填写]」（Agent 不代填）。
```

## 汇总

将已确认项用 3–6 行 bullet 复述给用户（**必须含专利类型**，含默认值），再进入 `project_scan.md` 对应的扫描阶段。

## 总结性反问（材料更偏实用新型时）

在 **Step 1 汇总之后**，或 **Step 2 扫描 / Step 6 预览** 发现材料明显更偏**产品形状、构造或其结合**的改进（卡扣、散热布局、支架、机械结构等），且当前仍为默认「发明」时，**须反问一次**（勿反复打断）：

```
当前按「发明」推进。材料更像产品形状/构造改进（结构件、装配关系等）→ 是否改为实用新型？
回复「维持发明」或指定类型即可。
```

用户确认后再切换封面表「申报类型」与查新 `--type`；未回复则维持发明。
