# 静默失效审查

## 核心洞察

**不报错的东西最难发现。**

一个失效的校验，产生的输出与「检查通过」**完全相同**。你以为有防护，实际是空的——两者从结果上无法区分。

所以校验逻辑写完，必须**主动验证它能失败**。不能失败（或从不失败）的校验，等于没有。

> 判据：一条规则如果**从未报过**，它要么真的干净，要么是哑弹。你必须能区分这两者，而不是假设前者。

---

## 三类静默失效

### 1 · 哑弹守卫（dead guard）

入口条件恒真/恒假，函数直接 return，**从未执行过**。

**实例**（真实案例）：
```python
if ZONE_COL not in H or 'PB' not in H:   # 想检查「有没有 PB 列」
    return
```
但表头里实际列名是 `PB(市净率)` → `'PB' not in H` **恒为 True** → 永远 return。
症状：该检查项 6 个月零命中，没人发现。

**排查**：把每个早退条件**逐个人工代入真实数据**，问一句：
> 「在正常输入下，这个条件**可能**为真吗？」

若答案是「不可能」或「永远为真」，就是哑弹。常见成因：
- 列名/键名写成简称（`'PB'` vs `'PB(市净率)'`）
- 判断方向写反（`in` 写成 `not in`）
- 前置条件本身互斥（`A and not A`）

### 2 · 静默空值（silent empty）

查询函数对「找不到」返回空字符串 / None / 默认值，**调用方无法区分「取不到」与「真的是空」**。

**实例**（真实案例）：
```python
def g(row, col):
    i = IDX.get(col)
    return row[i].strip() if i is not None else ''   # 列名写错 → 静默返回 ''
```
后果：页面「看着正常、数据全空」——比报错难查得多。

**排查**：
- 所有「按键取值」的函数，改为找不到时**抛错**或返回可区分的哨兵值
- 若不能改调用方，则加一道**引用完整性闸门**：`{代码里引用的键} − {实际定义的键} = ∅`，非空即中止并列出缺失项
- 闸门要**只扫代码行、排除注释**（否则注释里的示例文字会被误判为引用）

### 3 · 失效豁免 / 白名单（stale exemption）

「已知例外」清单里的条目，在规则或数据变更后**不再匹配任何实际违规**——它不报错，只是安静占位，**让基线虚高、掩盖真实状态**，同时占掉一个本可捕捉新问题的位置。

**排查**：遍历清单，验证每条都**精确对应一处现存违规**。对不上的即幽灵条目。
- 匹配键必须由**同一个函数**生成（手写易错——实战中写错过 3 次）
- 建议提供 `--fix` 自动清理，并**先备份再改**

## 方法：阳性注入测试

对每个校验单元，构造**已知会触发**的输入，断言它被检出。

```
对每条规则 R：
  1. 造最小违规样本（真实结构 + 故意违规值）
  2. 跑校验，收集实际报出的规则集合
  3. 断言：预期报出 == 实际报出
  4. 退出码非 0 = 有规则漏检（可作门禁）
```

### 关键细节

- **样本用不存在的标识**（假 ID / 假代码），避免撞上豁免/白名单被静默吞掉
- **工具本身也要验**：新写的审查工具，先注入一个已知坏例，确认它会报——否则工具自己就是哑弹
- **修复后重跑**：确认从「检出 N/M」变成「检出 M/M」
- **复用真实结构**：样本复制真实数据的一行再改，不要手搓 schema（否则测的是 schema 错误，不是规则）

---

## 何时跑

| 时机 | 为什么 |
|---|---|
| 新增 / 修改任何校验规则后 | 新规则最容易是哑弹 |
| 改口径、改词表、改数据结构后 | 会让**旧豁免键失效** |
| 发现「某规则长期零命中」 | 零命中 ≠ 干净，可能就是哑弹 |
| 定期 | 规则会随业务漂移 |

## 陷阱（都踩过）

| 陷阱 | 说明 |
|---|---|
| **用固定阈值替代变量** | 判据若依赖「当前值 / 所处位置」，用常数替代会在**某个区间必然误报**。宁可只保留确定性判据，把模糊判断交给专项规则 |
| **豁免匹配键写成截断版** | 匹配键须由同一函数生成。手写截断版会静默失配（实战写错 3 次） |
| **只测「该报的报了」** | 也要测「**不该报的不报**」——否则误报会淹没真信号，进而催生「随手豁免」，整套体系就死了 |
| **忽略退出码** | 校验脚本必须以**退出码**表达结果，否则无法作门禁、无法进 CI |
| **一次上线大批新规则** | 会爆上百条存量问题 → 门禁当天变红 → 有人开始随手豁免。**新规则先落 warning，存量清零后才升 error** |
| **正则太宽** | 抓引用/模式时，正则太宽会把注释、文档字符串里的示例也算进去。先收紧再上线 |

## 落地清单

```text
□ 每个早退守卫，人工代入真实数据验一遍（可能为真吗？）
□ 按键取值函数：找不到时抛错 / 加引用完整性闸门
□ 豁免清单：每条都能对上现存违规吗？有 --fix 吗？
□ 每条规则都有阳性样本吗？跑一遍，N/M 是否 = M/M？
□ 审查工具自身被验证过吗？（注入已知坏例 → 会报吗）
□ 「不该报的不报」测了吗？
□ 退出码能作门禁吗？
□ 新规则是否先落 warning？
```

## 一句话总结

> **不要问「这段校验写对了吗」，要问「它失败过吗」。**
> 只有见过它报警，你才知道它活着。
